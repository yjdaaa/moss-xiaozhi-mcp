# 开发规范

这份文档面向项目贡献者，说明代码组织、测试、安全和文档维护要求。具体行为以源码、测试和公开文档为准。

## 项目结构

- moss_mcp/：MCP 桥接、工具注册和本地 Web 服务入口
- core/：可复用的共享逻辑和硬件集成
- tools/：MCP 工具模块，每个模块提供 register_tool(mcp)
- apps/：Web 应用和 Excalidraw 画板
- tests/：Python 单元测试
- docs/：用户、开发者、激光和集成文档
- scripts/：平台启动脚本

不要为了“看起来整齐”新增重复的发送器、配置层或通用工具。只有当多个模块确实需要复用时，才把逻辑放入 core/。

## 代码约定

- 新增 MCP 工具必须实现 register_tool(mcp)。
- 将校验、转换、依赖加载和外部调用放在可测试的模块级函数中，保持注册 wrapper 简单。
- 环境变量读取集中在模块级常量或配置 helper 中，避免同一配置在多处重复解析。
- Windows、macOS 和 Linux 行为有差异时，显式分支并返回清晰的“不支持”原因。
- 保持已有模块名和公开工具名兼容；不要随意修正历史拼写导致导入链路失效。

## 安全边界

- .env 只存本机配置，真实 token、密码、设备 IP、串口号和私有路径不得提交。
- 激光、串口、网络设备、摄像头、桌面自动化和本地命令都按高风险能力处理。
- 生成图片、G-code、预览和推荐参数不等于启动机器。
- 完整文件发送、运动、开激光、切割和危险单命令必须经过代码中的确认门禁。
- 发送前应使用只读设备探测；设备不可达时直接结束，不重试、不继续发送。
- 前端只能调用后端 workflow，不得直接连接激光控制器或发送任意控制命令。
- Web 服务默认只绑定本机，不要暴露到公网。

## 测试要求

使用 Python unittest 和 unittest.mock：

    python -m unittest discover -s tests

- 串口、HTTP、Telnet、摄像头、GUI、子进程和本地应用必须 mock。
- 测试成功、无效输入、缺少依赖、平台差异和安全门禁。
- 不依赖本机可变的材料库、运行时目录或真实设备状态。
- 前端测试在对应应用目录执行 npm test，构建执行 npm run build。

## 文档维护

- 用户可见功能变化同步 docs/developer/feature-glossary.md 和相关用户文档。
- 激光硬件、命令和安全说明统一放在 docs/laser/。
- 小智/MOSS 提示词只维护在 docs/integration/xiaozhi-prompts/，修改时更新 latest.md 和日期快照。
- 文档示例使用 <device-ip>、<token>、<path> 等占位符，不写真实连接信息。
- 提交前检查 Markdown 链接、旧路径、绝对路径、局域网 IP 和敏感字段。

## Pull Request 检查清单

- [ ] 变更范围与目录职责一致。
- [ ] 新工具包含 register_tool(mcp)，并有对应测试。
- [ ] 外部效果使用 mock，没有连接真实设备。
- [ ] 没有提交 .env、运行产物、虚拟环境或个人配置。
- [ ] README 和相关 docs/ 链接仍然有效。
- [ ] 已运行受影响的测试和前端构建。
